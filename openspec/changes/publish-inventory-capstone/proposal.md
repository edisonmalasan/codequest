# Proposal

## Why

The reviewed Foundations course now teaches Q01–Q24, but its approved O8 inventory-manager capstone is absent. Phase 30 supplies a meaningful integration project and captures the required debug explanation and transfer response without mistaking deterministic feedback for reasoning assessment.

## What Changes

- Author and publish one versioned, non-guest capstone after Q24 in Integration, preserving every instructional snapshot and stable completion/reward identity.
- Supply record contracts, incomplete helper signatures, a defective helper to repair, learner-chosen data, graduated hints, explicit rubric and a fresh transfer task. Assess taught logic only; use existing console output as accessible supplied presentation.
- Add optional parent-defined written response fields to Editor Workspace, using its existing owner/version-bound draft save lifecycle. Capture responses only on explicit Submit.
- Extend the bounded private report with optional capstone responses. Backend acceptance requires both nonblank explanation and transfer responses for capstones, independently of reported functional pass; response presence is not quality grading.
- Keep responses inside the immutable report/outbox envelope, expose them for owner-only recovery, and retain exact replay and first-completion semantics.
- Record instructional/technical self-review and actual isolated reference/alternative/defect and learner-flow checks before selecting publication.

## Capabilities

### New Capabilities

- `foundations-capstone`: approved inventory project, declared rubric, bounded checks, response presence and reviewed publication.

### Modified Capabilities

- `javascript-foundations`: retain exactly 24 instructional quests while allowing the separately identified final capstone.
- `attempts-and-submissions`: require bounded written-response presence for capstone acceptance, preserve immutable reports and replay.
- `editor-workspace`: optional reusable response fields share owner-bound local draft persistence and explicit snapshot submission.

## Impact

Backend Git content, report normalization/acceptance, OpenAPI report documentation and generated contract if changed; frontend workspace and recovery presentation; focused backend/frontend/production Chromium tests and documentation. Existing Worker isolation, report/source limits, auth, prerequisite, progress, XP and acceptance-day streak rules remain in force. No database migration or dependencies are expected: existing JSON report and Dexie draft primitives suffice.

Phase 31+ analytics, AI, deployments, sharing, remote execution, manual review workflow, LLM grading, assessed DOM/events, cloud source merging and independent-certification claims are excluded. F04 reward/difficulty balance remains explicitly provisional; learner observation and F02/F06 pre-beta obligations remain open.
