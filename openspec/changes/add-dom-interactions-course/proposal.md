# Proposal

## Why

R08 still has no published browser-interaction Course. The existing isolated interactive adapter works in synthetic review, but the production catalog deliberately rejects interactive selection until an original Quest and its exact integrated build pass the R08 publication gate.

## What Changes

- Author a complete, original, twelve-Quest DOM Foundations Course in the existing Web Foundations Journey. Four ordered chapters move from selecting supplied elements and changing text through events, state, and an integrated small interface. The Course requires the completed HTML, CSS, and JavaScript foundations and does not expand guest eligibility.
- Use only the existing bounded HTML/CSS/JavaScript descriptor, supported DOM facade, inert preview display, data-only `interactive-text` checks, and explicit personal-learning Submit contract. Keep other published courses and their stable identities intact.
- Review all exact authored versions and assessments, including reference, valid alternative, defect, accessibility, and prerequisite coverage. Stage an atomic full-Course selection on the candidate branch; merge its publication only after the first selected Quest and complete Course pass the exact-build published-route containment, recovery, and lifecycle gates.
- Replace the unconditional production-catalog rejection only for selected interactive snapshots carrying approved review and exact-build evidence. Missing, stale, failed, or mismatched evidence continues to fail publication closed.
- Record the technical and curriculum review separately from founder acceptance and release readiness. R04 real-provider Auth, hosted/physical verification, and paused Phase 38 remain open.

## Capabilities

### New Capabilities

- `dom-foundations`: Original, complete browser-interaction Course content, assessment, publication, integrated learning flow, and exact-build safety acceptance.

### Modified Capabilities

None. Existing `interactive-web-execution`, `published-quest-workflow`, `curriculum-content`, `curriculum-api`, and `validation-engine` requirements already define the required boundaries. This change implements their deferred selected-Quest gate without relaxing it.

## Impact

Affected areas are `backend/content/` and its publication validator/catalog, the existing interactive browser test harness and authoring review tools where needed, frontend published-route integration tests, and R08 evidence/roadmap documentation. No new service, dependency, database migration, API shape, remote runner, application-origin learner execution, or independently verified grading is proposed.
