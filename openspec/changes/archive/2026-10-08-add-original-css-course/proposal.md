# Proposal

## Why

The published web Journey currently ends with HTML. R08 requires a complete original CSS Course that learners can discover, finish, and revisit through the integrated workspace. The existing static preview supports CSS display, but local CSS Check and authoring tools cover only a small declaration subset, so a full beginner sequence needs bounded extensions before publication.

## What Changes

- Author a distinct CSS Foundations Course in the Web Foundations Journey with four ordered chapters, twelve original instructional Quests, an integrated final page, and reviewed versioned lessons, starters, hints, and assessments. Keep the Course unpublished until the entire selected inventory passes review.
- Extend static web Check with a bounded, data-only CSS rule contract for taught selectors, declarations, and responsive media conditions. State that Check verifies declared source structure and values, not computed visual quality or independent mastery.
- Add local authoring candidate checks for complete HTML/CSS snapshots, including passing reference and alternative solutions and deliberate defects, without executing learner code in the backend or authoring process.
- Give learners explicit narrow and wide static preview widths so responsive exercises can be inspected while keeping the existing separate origin, script-disabled iframe, CSP, and source recovery guarantees.
- Verify catalog-to-final-project traversal, accessibility, source persistence, backend-accepted completion, trusted progress and XP, and regression protection for the existing HTML and JavaScript courses.

## Capabilities

### New Capabilities

- `css-foundations`: Complete original CSS Course, coherent progression, safe static exercises, reviewed publication, and integrated learner flow.

### Modified Capabilities

- `validation-engine`: Bounded declarative CSS assertions for the CSS Course, including reviewed responsive rule scopes.
- `curriculum-authoring-tools`: Targeted HTML/CSS candidate checks against selected authored snapshots.
- `web-preview-runtime`: Explicit bounded viewport choices for inspecting static responsive styles without changing sandbox authority.

## Impact

Backend Git curriculum and publication selection, authoring command, static web case schema and API projection, frontend static validation and preview UI, relevant canonical specs, content review documentation, and browser tests. No new database authority or migration is expected. Existing authenticated Submit, personal-learning acceptance, XP ledger, runtime isolation, guest eligibility, and interactive publication gate remain unchanged. Founder acceptance of the exact Course build and R04/Phase 38 evidence remain separate.
