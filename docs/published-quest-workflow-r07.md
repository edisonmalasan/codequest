# R07 published Quest workflow

The published Quest supplies one optional versioned `exercise` descriptor. Existing snapshots without it keep the single JavaScript editor and Worker Check. A selected static web descriptor supplies identified HTML and optional CSS files, an isolated static preview, and bounded declarative HTML/CSS checks. Interactive web descriptors are supported by the local Worker and preview adapters, but catalog publication is blocked until original R08 content and a separately reviewed exact-build published-route security record exist. A development exercise is not a published course.

## Learner flow and authority

The desktop lesson keeps reading, editing, and results in three persistent regions. Tablet and mobile use the existing region controls so the learner can switch between Lesson, Code, and Results without remounting the editor. The editor keeps each file's draft under owner, Quest, content version, and for web exercises assessment version and mode. An idle save, visibility change, and page-exit attempt use the existing draft repository; the sequence navigation withholds its links while a write is pending or has failed. Browser navigation and storage failures can still interrupt a write, so the learner should use Save locally and copy source if storage is unavailable.

Run executes JavaScript through the isolated Worker only where that mode supports it. Static web Preview renders HTML/CSS through the dedicated preview origin with active content filtered. Local Check is an immutable source snapshot: JavaScript uses the existing Worker strategy; static web parses inert HTML/CSS; interactive checks use only authored event/text assertions through the isolated interaction adapter. Editing any file invalidates the prior Check. A Check gives local feedback and does not claim account completion.

An authenticated learner explicitly selects Submit after a current Check. A failed Check may be recorded as an attempt but cannot grant completion. A web source is canonical JSON containing schema version, Quest ID, content and assessment versions, mode, and ordered stable file IDs/languages/source under the existing 64 KiB total limit. The owner-scoped outbox preserves source and client event ID through uncertain delivery. NestJS compares the bundle to the selected published descriptor, enforces the current version and prerequisites, records the attempt, and applies the existing personal-learning acceptance policy. The backend does not execute learner code. Only backend facts drive accepted progress, XP, streak, and unlock presentation; the current client report is not independent grading or a competition/certificate claim.

Back and Next follow the published Journey and Chapter order. Authenticated availability comes from the owner-scoped backend progress read. Guest Q01-Q04 navigation and completion remain labeled provisional and device-local; version-mismatched guest work does not unlock a current Quest. Missing progress, stale content, locked prerequisites, offline route data, or a failed draft save produce an explanation and a Journey map or downloaded lessons recovery link instead of an unlocked claim. A completed Quest remains available for revisit.

## Publication and verification state

The catalog requires Quest-level curriculum and technical review for a static web selection. An interactive selection also needs a dated exact-build evidence record, and the loader currently blocks it even when review fields and a record reference are present. A later reviewed change must verify the authored subset on the exact published build and explicitly revise that gate. No interactive Quest is selected in the production curriculum.

Local development checks cover the static published-route fixture, JavaScript compatibility, multi-file Check snapshot invalidation, owner/version-bound replay, and isolated interactive recovery. The published interactive route, real provider authentication, founder acceptance, and release-hosted evidence remain separate open gates. The R07 Apply task list is the authoritative verification checklist for this change.
