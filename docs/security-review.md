# Phase 33 security review

Reviewed 2026-09-30 against the repository at the Phase 33 Apply branch. This is a source and local-test review, not a production penetration test or permission to collect learner data.

| Boundary | Observed control and repeatable evidence | Remaining check or owner action |
| --- | --- | --- |
| Bearer identity and session lifetime | `SupabaseTokenVerifier` verifies asymmetric signature, issuer, audience, UUID subject, and required bounded `iat`/`exp`; `AuthenticationGuard` returns one safe `401`. `backend/src/modules/identity/auth-token-verifier.spec.ts` and `identity-guards.spec.ts` cover malformed, forged, stale and overlong claims. | Deploy with `SUPABASE_AUTH_MAX_TOKEN_AGE_SECONDS` matched to the actual Supabase Auth token lifetime; verify live refresh, key rotation, clock behavior and session expiry. Do not log token text. |
| Owner and permission enforcement | All current account, attempt/import/replay, progress, XP, and streak controllers declare `AuthenticationGuard` and `PermissionGuard`; protected handlers declare backend permissions and pass `principal.userId` to services. `backend/src/application.spec.ts`, `modules/identity/identity-guards.spec.ts`, and learning/progress service tests exercise forged selectors and owner-bound records. Curriculum and health are intentionally public. | Recheck each new route, including privileged author/operator routes if added. This release has no administrator or author API surface. |
| API inputs, origins and abuse | `ValidationPipe` rejects unknown DTO fields; Fastify bounds request bodies; backend config bounds numeric limits and permits explicit HTTPS CORS origins only in production. `backend/src/application.spec.ts`, `infrastructure/config/backend-config.spec.ts`, and curriculum API tests exercise DTO, CORS, payload and throttling cases. `ThrottlerGuard` is global but its store is process-local. | At deployment, enforce TLS and ingress limits across instances; verify proxy trust and real client IP handling without accepting arbitrary forwarded headers. A local throttler is not a distributed abuse guarantee. |
| Learner execution and preview | The JavaScript and validation bootstraps use dedicated credential-free hosts, restrictive CSP, bounded correlated channels and fresh Workers; preview is a script-disabled opaque HTML/CSS frame with JavaScript computation separately in a Worker. Trusted app headers do not add `X-Frame-Options` to those hosts. Runtime, preview, PWA and browser tests cover isolation/recovery. | Recheck host routing, CSP, cookies and sandbox flags on actual deployment origins and target devices. Browser process memory is not a hard quota. No DOM scripting is authorized in preview. |
| Database access | Backend alone holds the application database connection. Tracked migrations create `codequest` tables and do not issue `GRANT` to browser roles; owner queries and unique facts are exercised in PGlite/PostgreSQL integration tests. | Source inspection cannot establish hosted Supabase grants, RLS or credential privilege. Inspect the live database roles/schema grants and use a least-privileged application credential before beta; test anonymous/authenticated direct access is denied. Never expose application table credentials to the browser. |
| Storage and secrets | Route inventory contains no learner upload or public code-publishing endpoint. Frontend configuration uses publishable Auth fields; backend database and telemetry secrets remain backend environment values. Tracked-file inspection found no `.env` files or service-role material. | No Supabase Storage bucket policy or upload-validation claim is made because uploads are outside MVP. Audit deployed secret stores, bundles, logs and rotation. Review any future upload capability separately. |
| Privacy, analytics and monitoring | PostHog/Sentry delivery remains gated off pending F06; existing telemetry allowlists exclude raw source, tokens and protected responses. PWA caches only allowlisted public shell resources and keeps drafts device-local. | F06 still requires approved consent, retention, deletion and operator-access rules before real learner data collection. Review live SDK configuration and retention at the release gate. |
