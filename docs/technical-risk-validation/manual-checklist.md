# Remaining manual evidence procedure

Use [charter](charter.md) B01–B09 unchanged and [report](report.md) for known unsafe prototype behavior. Execute only synthetic fixtures in a task profile; do not use real credentials. Do not run the tight-loop preview manually: it has already required emergency browser termination in automation.

Before each session record operator, exact physical hardware/OS/browser versions, viewport/input method, power/network state, installation mode, assistive-technology version/configuration, candidate, prototype commit, frozen generated asset names/SHA-256 values, and dated trial IDs. Unavailable configurations stay untested. Record failures and original/retest links; do not fill gaps with viewport emulation.

1. Windows Chrome and Firefox: record installed versions/access; type, paste, undo, indent, select and reset Q01 source. Test output access and preserved source across resizing. Collect B01's 10 warmup/100 measured input-to-visible-frame samples without averages hiding p95. The Windows machine is confirmed; no operator interaction has been claimed.
2. Android/iPhone, when access is confirmed: repeat typing/selection/touch, virtual-keyboard visibility, rotation, focus and short exercises. Record B08's 30 mobile run cycles. Declare a lower-powered device before B01/B07 measurements.
3. Keyboard/AT: navigate instructions/editor/Run/Check/errors/results, escape the editor, copy recovery source, apply/cancel reset and reach textual preview output. Record NVDA/VoiceOver exact pairings when supplied. Check zoom/reflow and reduced-motion preferences. Do not infer screen-reader usability from DOM assertions.
4. Runtime: reproduce success/syntax/error/wrong-check/flood/loop fixtures using the already bounded Worker procedure; collect raw timeout/fresh-run samples and B08's desktop/mobile cycles, source comparisons, crash/cleanup/memory observations. Keep hard memory quotas unverified unless instrumentation establishes them.
5. Offline/PWA: record installation support separately from browser learning. Prepare public lesson/runtime and exact saved source, close the actual browser/home-screen process, disconnect, relaunch and complete local Q01 checking. Collect B07's 10 physical cold-launch trials. Missing resources must fail truthfully. No account acceptance/XP/streak is earned offline.
6. Persistence: verify injected and actual unavailable/full/cleared storage behavior, interrupted save, background/restart and explicit local-loss limitations using only task-origin data. Execute B09's eight reload, six update and six multiclient cycles, including unsaved source, immutable pending snapshots and compatible/incompatible assessment identities. Record source/version comparisons per cycle.
7. Integrated acceptance: complete Q01 read/edit/fail/hint/correct/check/provisional/save/reload/offline/recovery, then explicit guest import/owner change/expiry/lost-response retry. Record simulation labels and no duplicate simulated reward. Combined preview/update containment awaits a tested redesigned candidate.

Review checklist for the project owner: technical reproducibility and complete gates; security origin/network/session/message/CPU findings and accepted P06 trust limitations; product Q01 concepts/text equivalents/mobile expectations and F02 coverage. Record a dated Proceed, Redesign/no-go or Inconclusive result with limitations. Role assignment and proposal approval do not approve the evidence or authorize Phase 2.
