## Why an adjustment is necessary

Installed Windows Chrome is accessible through Playwright/CDP. No dedicated Codex Browser Use or OS computer-interaction tool is exposed in this session. Browser automation can exercise native Chrome, keyboard events, actual browser zoom where accessible, reflow, media preferences, storage and browser processes. It cannot establish touch/virtual-keyboard/rotation behavior on inaccessible physical phones, native Safari behavior, NVDA/VoiceOver spoken comprehension, physical input latency, OS restart behavior or hard memory isolation. The owner prohibits asking for manual user validation. Missing equipment is untested, not unsupported.

The current spec explicitly requires physical Windows Chrome/Firefox, macOS Safari, Android Chrome, iPhone Safari/home-screen, one declared lower-powered physical device and assistive technology. Its unavailable-device scenario makes the overall gate inconclusive. Its production-gate requirement additionally requires all applicable device/integrated/offline/update gates and dated technical/security/product review. These cannot truthfully be marked passed by automation alone.

B02/B03 deadlines, B04-B06 byte/message/output limits, B08 desktop cycle counts and B09's exact 8 reload / 6 editing-update / 6 multiclient mix remain unchanged for the eligible baseline.
