## Candidate comparison and failure evidence

The opaque candidate uses a sandboxed `srcdoc` frame with `allow-scripts`, a Blob Worker and inherited CSP. Its policy is `default-src 'none'; script-src 'unsafe-inline' 'unsafe-eval' blob:; worker-src blob:; connect-src 'none'; frame-src 'none'; form-action 'none'; base-uri 'none'`. Public Worker bytes are inline bootstrap data; learner source is passed only after bootstrap. Sender checks bind the actual frame window; decoded results bind run/task/content/assessment identity.

The dedicated candidate uses a distinct-origin bootstrap with `allow-scripts allow-same-origin`; it is never an authenticated application origin. Bootstrap CSP allows only its own scripts/Worker, with connections/frames/forms denied. Worker response CSP is `default-src 'none'; script-src 'unsafe-eval'; connect-src 'none'; worker-src 'none'`. It depends on separately reachable bootstrap assets; physical HTTPS and offline dedicated-origin loading are unverified. No candidate is selected as production-safe. Opaque execution is the more promising Chromium/offline investigation candidate, subject to missing coverage and host-allocation limitations.

The baseline preview sandbox is `allow-scripts` without same-origin privilege. Its own CSP denies network resources, frames, connections and forms while allowing inline scripts/styles. Nevertheless, learner `location.href` produced **GET `/self-navigation?fixture=SELF_NAV`** at the sink. See [original evidence](evidence/automated-2026-09-13T06-21-23.357Z.json). A successful diagnostic test means evidence was collected; `policyPassed: false` is a security failure.

Adding parent `frame-src 'none'` at `/?framePolicy=none` denied the tested self-navigation and left opaque Worker execution usable in [serial evidence](evidence/serial-2026-09-13T06-28-05.003Z.json). It is only a comparison variant. It does not establish the dedicated frame's compatibility or comprehensive network denial across engines.

Even with that parent policy, `<script>while(true){}</script>` starved recovery. The [separate-process watchdog evidence](evidence/preview-loop-2026-09-13T06-31-47.393Z.json) records `PROBE_STARTED`, expiration of the 8-second emergency cutoff and termination of only the owned child/browser/server tree. B02 requires the 2-second execution deadline plus at most 1-second recovery. Emergency process termination fails that criterion. Origin restrictions do not establish CPU isolation.

## Verification and retained history

The timestamped [evidence directory](evidence/) retains initial failures and retests. The final complete Chromium run passed **22/22** cases including lost-response/version reconciliation and additional channel/message/preview-reset probes; earlier passing and failing runs are retained. See [final Chromium evidence](evidence/automated-2026-09-13T06-44-45.842Z.json), recorded against commit 140b114 with complete asset hashes frozen before trials. The 18 protocol/mock unit tests passed. Strict application TypeScript and separate WebWorker TypeScript checks, ESLint and the Vite/Serwist build passed. Built main JS is approximately 832 kB / 273 kB gzip with eight precache entries, approximately 819 KiB; Vite emits its large-chunk warning. These sizes are observations, not passing physical startup budgets.

Initial tests exposed a debounce race losing the latest draft during owner changes and a malformed quoted test fixture. Saving before owner/task transitions fixed source loss; both regression checks passed. Initial update verification reloaded during service-worker activation; the retest waits for actual activation, then verifies both clients' retained source. An initial records probe expected numeric `5`, but the documented protocol transports textual `"5"`; its assertion was corrected, with no change to protocol semantics. The [corrected serial retest](evidence/serial-2026-09-13T06-45-02.049Z.json) passed the records fixture; the original failed assertion remains retained.

Some earlier browser/check attempts failed with Windows committed-memory exhaustion (`VirtualAlloc`, V8 allocation failure, worker exit 134/3221226505 or crashed targets). They do not establish a learner-boundary failure or a browser pass. Runs were retried serially with reduced process overhead; no unrelated user processes or system pagefile settings were changed. One initial full-suite attempt was stopped by terminating only its owned Playwright process tree and did not produce a completed reporter file. One watchdog startup attempt itself exhausted memory before producing a record; the later completed watchdog record above establishes the actual preview failure.

Firefox launch reported missing `msvcp140_1.dll`; Firefox cases remain untested. WebKit launched but could not create a page, so WebKit cases remain untested/inconclusive, not Safari passes. No runtime libraries were installed system-wide.

`pnpm test`, `pnpm lint` and `pnpm typecheck` were attempted at repository root: each failed because `pnpm` is not on PATH. `corepack pnpm@10.30.3 test` at root reported `ERR_PNPM_NO_IMPORTER_MANIFEST_FOUND`: there is deliberately no root production package. Prototype checks ran inside their own directory; no fake production commands were added.

Process/evidence capture deviation: the charter required exact asset hashes before the first candidate measurement, but those first dirty-build runs did not freeze a complete manifest. The serial runner freezes the listed asset SHA-256 values before its trials. Those later hashes do not retrospectively certify earlier builds; the final 22-case Chromium run freezes the complete built asset manifest before trials. Required physical/other-engine trials still need the same prospective capture. B01/B07/B08/B09 physical criteria are unchanged.
