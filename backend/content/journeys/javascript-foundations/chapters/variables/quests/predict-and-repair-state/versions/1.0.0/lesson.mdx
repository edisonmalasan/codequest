## Goal

Trace assignment order and repair a variable-name and stale-output defect.

## Learn

A print captures the value when that instruction runs. It cannot predict a later assignment. `let gate = "closed"; console.log(gate); gate = "open";` prints closed, even though the final state is open.

Names must match exactly. A misspelled name such as `gat` is not an alias for `gate`. Before running a small program, write down its expected state after every assignment; compare that prediction with the output.

## Worked example

```js
let gate = 'closed';
console.log(gate);
gate = 'open';
console.log(gate);
```

## Your task

Start `supplies` at 4 and print it. Then assign 2 and print the updated value. Finally assign 0 and print it. Repair the starter's misspelled name and move the middle print after its assignment. Predict all three lines before Run.

## Check contract

Print the initial, intermediate and zero-boundary states in that order. The reflection is a self-explanation, not an automatically graded answer.

Complete console output, one value per line:

```text
4
2
0
```

## Reflect (ungraded)

Which defect would stop execution, and which would run but print the wrong state? Explain the first differing line. Write or say your explanation for yourself. Check does not assess this reasoning.

## If you get stuck

A syntax error means JavaScript could not read the program: inspect quotes, brackets and punctuation. A runtime error happens after it starts: inspect names and the failing operation. A failed check means the program ran but its behavior differs: compare the declared example with the observed result. Use the graduated hints one at a time. Keep loops bounded; a timeout stops the run and preserves your code.
