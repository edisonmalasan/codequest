## Goal

Diagnose an excluded endpoint using empty, single-step and multi-step examples.

## Learn

An off-by-one defect visits one too few or too many values. Trace initialization, first condition, last admitted value and first rejected value. A large example can hide the cause; a one-step example often makes it obvious.

Different contracts need different endpoints. Summing 1 through a limit includes the limit, while waiting until a target is reached stops before another update. Choose the comparison from the required behavior, not from a rule that every loop uses `<`.

## Worked example

```js
let sum = 0;
for (let n = 1; n <= 2; n = n + 1) {
  sum = sum + n;
}
console.log(sum);
```

## Your task

Repair the three loops that sum integers 1 through limits 0, 1 and 4. Keep the accumulator starts and updates. Explain which missing iteration causes the incorrect total at limit 4. Print one final result per scenario.

## Check contract

Nonnegative integer limits, inclusive endpoint and no intermediate prints. The zero limit sums an empty sequence. Check observes results, not your explanation or choice of loop syntax.

Complete console output, one value per line:

```text
0
1
10
```

## Reflect (ungraded)

Propose a small revealing test and explain why the one-step case detects the missing endpoint. Write or say your explanation for yourself. Check does not assess this reasoning.

## If you get stuck

A syntax error means JavaScript could not read the program: inspect quotes, brackets and punctuation. A runtime error happens after it starts: inspect names and the failing operation. A failed check means the program ran but its behavior differs: compare the declared example with the observed result. Use the graduated hints one at a time. Keep loops bounded; a timeout stops the run and preserves your code.
